archplan

Plan an architecture change, then let an agent build it. The as-is model comes from the code. You edit the to-be model. The difference becomes a plan.

The screen

  • Left: the plan. The intent at the top says what the change should achieve. Below it come the rules, the tasks and the comment threads. A thread about a task sits under that task. The narrow column on the far left jumps to each part.
  • Right: the diagram. The toolbar picks the view (Components, Types, Sequences, Glossary) and the mode (As-is, To-be, Diff). Focus narrows the diagram to a few components. View holds the settings that hide or filter things; its number says how many are on. Overlay colours the boxes.
  • Item pages. Click a box, a line or a call to open its page on the left. The page shows the details and the edits you can make. Click Plan in the breadcrumb, or press Esc, to go back.
  • Header. The pill shows what Claude did last. Search finds any component, type, task or action. Share copies or downloads the plan, the diagram as D2 and the target model. ⋯ opens files, exports from the code, resets the target, sets the theme and opens this help.

Start here

  1. Look around. Pick a view. Type in Focus to zoom in on one part, or double-click a box. Hide leaves (in View) hides boxes with at most one incoming line and no outgoing ones, and then the boxes that only led to them. What is left are the connections that matter.
  2. Say what you want. Write the intent at the top of the plan.
  3. Edit the to-be model. Click an item and change it on its page: move a type, rename it, forbid a dependency. Drag the blue dot from one box to another to connect them. Select a line and press Delete to remove it. To add a type or a package, or to read the model as text, open Edit the model at the end of the plan. Diff shows what you changed.
  4. Comment. Write on an item's page. Shift-click several items to comment on them together, for example an import cycle. Type @ to link a component, type or task. A comment on a selection keeps a small picture of it. Click the picture to get that view back.
  5. Hand over. The plan lists the tasks in order. Claude reads it directly. Check against the code, at the end of the plan, shows how the result is verified.

Working with Claude

In Claude Code, with the archplan plugin, type /archplan in the repository. Claude sees your comments as you write them and answers in the same thread. An orange decision thread waits for your choice: click an option. A feedback thread only needs reading.

When Claude proposes a change to the target, it arrives as a suggestion. Its card lists each change. Untick the ones you do not want, then accept or reject. The card says how the plan would grow or shrink. With suggestion in the mode switch shows the change in the diagram, with new items dashed green. A change Claude makes directly shows in Diff, and Undo reverts it. After Claude changes the code, the model reloads and the plan shrinks.

Overlays

Change frequency colours each component by the number of commits that touched it in the last year. Co-change draws a purple dashed line between components that often change in the same commit. A thick line means there is no dependency between them: hidden coupling. Fan-in and fan-out colour components by how many others use them, or how many they use. The first two need git. Overlays work in the Components view.
